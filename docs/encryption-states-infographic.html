The Three States of Encryption

Data lives in three states — sitting still, moving, and being worked on. Each needs its own protection. The catch: while encrypted gibberish is perfect for storage and transport, a CPU can’t do math on gibberish — which is why encryption in use is the hard problem.

🔒 State 1
💾

At Rest

Data stored on disk, in databases, backups, or object storage. Nobody is touching it right now.

Threat: Stolen drives, leaked backups
Tools: AES-256, BitLocker, TDE, KMS

📤

In Transit

Data moving across a network — browser to server, service to service, region to region.

Tools: TLS/HTTPS, mTLS, WSS, VPN
✓ Gibberish is fine — it’s just passing through
⚠️ State 3
🧠

In Use

Data actively loaded in memory (RAM) and processed by the CPU — calculations, searches, model inference.

Threat: Memory scraping, rogue admin, malware
Tools: Confidential Computing, TEEs, HE
✗ Gibberish is useless — the CPU needs the real value

💡 Why “In Use” Is the Hard One

To store or send data, you never need to understand it — you just move the encrypted blob from A to B. But to compute on data, the processor must know what the numbers and letters actually are. Feed encrypted ciphertext into a CPU and it can’t add, compare, or sort it — the math is meaningless.

➞

✗ Math on gibberish fails

Must decrypt first
→ plaintext exposed in RAM

The dilemma: Traditionally, data must be decrypted into plaintext in memory before it can be used — creating a window where it’s exposed. Closing that window is the whole point of encryption in use, solved by approaches that let computation happen without ever revealing the plaintext.

How “In Use” Protection Works

Approach Idea Trade-off
Trusted Execution Environments (TEEs)
Confidential Computing — Intel SGX, AMD SEV, Azure Confidential VMs		 Decrypt only inside a hardware-isolated “enclave” that even the OS and cloud admin can’t peek into. Near-native speed, but trust depends on the hardware vendor.
Homomorphic Encryption (HE) Do math directly on the ciphertext — the result decrypts to the correct answer, plaintext never appears. Cryptographically elegant, but very slow / compute-heavy today.
Secure Multi-Party Computation (MPC) Split data across parties so no single party ever sees the whole value, yet they jointly compute a result. Strong privacy, high network/coordination cost.

At a Glance

State Where Can it stay gibberish? Maturity
At Rest Disks, DBs, backups Yes — ideal Mature & standard
In Transit Networks, the wire Yes — ideal Mature & standard
In Use RAM / CPU No — CPU needs real values Emerging & harder
Defense in depth = protect data in all three states. The weakest link defines your real security.
